# Reading the main thread

[Home](../README.md) · [中文目录](../README.zh-CN.md)

Start with a small number of systems whose code has visibly different jobs. Then read a sequence within a domain. This makes it easier to see which mechanisms recur and which dependencies remain specific to a task.

## A first pass in eight papers

| Order | Paper | Question to carry into the reading |
|---|---|---|
| 1 | [PAL](https://arxiv.org/abs/2211.10435) | Which part of an answer is produced by the language model, and which by execution? |
| 2 | [CodeAct](https://arxiv.org/abs/2402.01030) | When does writing one program help more than emitting separate actions? |
| 3 | [ViperGPT](https://arxiv.org/abs/2303.08128) | How does code organize visual expertise supplied by other models? |
| 4 | [Code as Policies](https://arxiv.org/abs/2209.07753) | What can be composed from the robot APIs already provided? |
| 5 | [Voyager](https://arxiv.org/abs/2305.16291) | What persists after an attempt, and how is it used in another task? |
| 6 | [CAD-Recode](https://arxiv.org/abs/2412.14042) | What does a construction program preserve beyond a final shape? |
| 7 | [LeanDojo](https://arxiv.org/abs/2306.15626) | What does a proof checker reveal after a failed or successful step? |
| 8 | [FunSearch](https://www.nature.com/articles/s41586-023-06924-6) | Why search for a program that generates a construction rather than the construction directly? |

## Follow a domain's development

**Visual reasoning.** [NS-VQA](https://arxiv.org/abs/1810.02338) → [VisProg](https://arxiv.org/abs/2211.11559) → [ViperGPT](https://arxiv.org/abs/2303.08128) → [PyVision](https://arxiv.org/abs/2507.07998). Follow the change from a fixed symbolic representation and fixed modules to more flexible tool construction. The visual front end still matters.

**Editable content.** [MatPlotAgent](https://arxiv.org/abs/2402.11453) → [SlideCoder](https://arxiv.org/abs/2506.07964) → [JanusCoder](https://arxiv.org/abs/2510.23538). Contrast with [Paper2Poster](https://arxiv.org/abs/2505.21497), [WavJourney](https://arxiv.org/abs/2307.14335) and [WavCraft](https://arxiv.org/abs/2403.09527): the executable code may be written directly, generated by a fixed compiler, or used mainly to orchestrate experts.

**3D and CAD.** [ShapeAssembly](https://arxiv.org/abs/2009.08026) → [DeepCAD](https://arxiv.org/abs/2105.09492) → [Real2Code](https://arxiv.org/abs/2406.08474) / [CAD-Recode](https://arxiv.org/abs/2412.14042) → [BlenderAlchemy](https://arxiv.org/abs/2404.17672) / [LL3M](https://arxiv.org/abs/2508.08228). This is a conceptual route, not strict chronology: compare recovering structure with editing an existing scene. Ask whether editability is demonstrated or systematically evaluated.

**Computer use.** [WebAgent](https://arxiv.org/abs/2307.12856) → [CodeAct](https://arxiv.org/abs/2402.01030) → [OpenHands-Versa](https://arxiv.org/abs/2506.03011). Use [OSWorld](https://arxiv.org/abs/2404.07972) as a reminder that browser access and full desktop interaction are different evaluation settings.

**Robotics.** [ProgPrompt](https://arxiv.org/abs/2209.11302) → [Code as Policies](https://arxiv.org/abs/2209.07753) → [Instruct2Act](https://arxiv.org/abs/2305.11176) → [VoxPoser](https://arxiv.org/abs/2307.05973). Branch to [Eureka](https://arxiv.org/abs/2310.12931) for reward code, [GenSim2](https://arxiv.org/abs/2410.03645) for generated training data, and [RoboPro](https://arxiv.org/abs/2501.04268) for API adaptation. The new [Learning and Transferring Closed-Loop Robot Software](https://arxiv.org/abs/2609.19906) is a priority for a deeper transfer-protocol audit; it is currently A in this collection.

**World models.** [WorldCoder](https://arxiv.org/abs/2402.12275) → [GIF-MCTS](https://arxiv.org/abs/2411.14499) → [Code2World](https://arxiv.org/abs/2602.09856) → [Programmable World Model](https://arxiv.org/abs/2609.10540). Before comparing results, write down whether each system predicts transitions, observations or persistent entity state.

**Formal mathematics.** [GPT-f](https://arxiv.org/abs/2009.03393) → [HyperTree Proof Search](https://arxiv.org/abs/2205.11491) → [Draft, Sketch, and Prove](https://arxiv.org/abs/2210.12283) → [LeanDojo](https://arxiv.org/abs/2306.15626) → [DeepSeek-Prover-V2](https://arxiv.org/abs/2504.21801) → [AlphaProof](https://www.nature.com/articles/s41586-025-09833-y). Track proof representation, search, training feedback, test-time compute and the translation of informal problems into formal statements.

**Scientific discovery.** [FunSearch](https://www.nature.com/articles/s41586-023-06924-6) → [AlphaEvolve](https://arxiv.org/abs/2506.13131); [Coscientist](https://www.nature.com/articles/s41586-023-06792-0) supplies a physical-experiment comparison. Read [SciCode](https://arxiv.org/abs/2407.13168) and [ScienceAgentBench](https://arxiv.org/abs/2410.05080) before equating a runnable script with a successful research result.

## Three questions for every paper

1. What exactly did the model write or change, and which tools, models or interfaces were already provided?
2. What feedback changed the next attempt, and who defined the objective and acceptance test?
3. What does the experiment support: multi-task coverage, reusable experience, training transfer, formal verification, or physical confirmation?

The complete metadata preserve reading depth. Follow A entries into their methods and experiments before making a numerical or causal claim from them.

## 中文阅读建议

先读上面的八篇入门文献，建立“代码具体做了什么”的认识，再沿专题深入。每次阅读都分别记下输入、代码产物、执行器、反馈和人的预设。最后读[证据比较](evidence.md)，尤其注意多任务覆盖与迁移、可运行与正确、形式证明与原题忠实性之间的差别。这样既能保留“Code Agents Unify the World”的主线，也能准确说明每项工作的实际贡献。
